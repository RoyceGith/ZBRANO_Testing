Connect your plugins

Step-by-step setup for your own ZBRANO installation. Keep this guide open in a separate tab while you configure the provider. Reviewed September 2026.

GitHub

You need a GitHub account and access to ZBRANO’s Home Assistant add-on configuration. ZBRANO uses device-code authorization with an OAuth App. The normal connection needs a Client ID; no client secret or manually created token is entered.

1. Register your OAuth App

  1. Sign in to the GitHub account that will own the app. Open Register a new OAuth application (Settings → Developer settings → OAuth Apps → New OAuth App).
  2. Use a recognizable name, such as ZBRANO Home. Set the homepage to your Home Assistant web address. GitHub also asks for an authorization callback URL: use your Home Assistant web address there. ZBRANO’s device flow does not redirect to that field.
  3. Register the application. In its settings, enable Device Flow and save. Copy the Client ID, not the app name or a client secret.

GitHub: registering an OAuth App · GitHub: device authorization

2. Configure ZBRANO

  1. In Home Assistant, open Settings → Add-ons → ZBRANO → Configuration. Enable optional configuration fields if they are hidden.
  2. Paste the Client ID into github_oauth_client_id. Save, restart the ZBRANO add-on, and reopen ZBRANO.
  3. Open Plugins → Catalog, find GitHub, and choose Connect with GitHub.

3. Authorize and check the connection

  1. Allow the sign-in popup. Copy the code shown by ZBRANO and enter it on GitHub’s device authorization page. Check the signed-in account before authorizing.
  2. Review the requested access. This connector requests repo and read:org, which include repository access and organization information. Your organization may require its own approval.
  3. Return to ZBRANO and leave it open while sign-in finishes. In Plugins → Installed, review the tools and enable the plugin if it is disabled. Check that it is healthy and available to chat.
  4. Try a read-only request: “List my GitHub repositories.” Verify that the results belong to the intended account.

GitHub troubleshooting

“GitHub sign-in setup required” or invalid Client ID

Check that the saved value is the Client ID from the OAuth App you created. Save and restart the add-on, then refresh the catalog.

Device flow disabled, expired code, or blocked popup

Enable Device Flow in that same app. Allow popups for Home Assistant. Start Connect with GitHub again to get a fresh code; do not reuse an expired code.

Wrong account or missing organization repositories

Use the intended account on GitHub’s authorization page. For a clean retry, remove the GitHub plugin in ZBRANO and connect again. Organization policies or SSO can restrict access; ask the organization administrator to approve the app where needed. Review authorizations in GitHub application settings.

Connection later stops working

Check the installed plugin’s error and refresh it. If authorization has expired or been revoked, reconnect. ZBRANO’s current GitHub device connector stores the access token and does not implement GitHub refresh-token rotation.

Gmail Direct

This is ZBRANO’s built-in connection to the standard Gmail API. It can search and read messages, list labels, and create unsent drafts after approval. It does not provide sending or deletion tools. No Workspace MCP developer-preview enrollment is needed.

1. Choose your Cloud project and enable Gmail

  1. Open Google Cloud Console. Use the profile menu to select the account that owns your project. In the top project selector, create a project or select your existing one.
  2. In that project, open Gmail API and click Enable.

2. Set up Google’s consent screen

  1. Open Google Auth Platform. Complete Get started if shown: choose an app name you recognize, support email, and contact email.
  2. In Audience, choose External for personal Gmail accounts. Internal is only for accounts in the relevant Workspace organization.
  3. For personal testing, leave the app in Testing and add the exact Gmail address you want to connect under Test users. Project ownership alone does not replace this step.
  4. Under Data Access → Add or remove scopes, add https://www.googleapis.com/auth/gmail.readonly and https://www.googleapis.com/auth/gmail.compose, then save. Google’s compose permission also covers sending; ZBRANO exposes only draft creation and requires approval for it.

Google: project and Gmail API setup · Google: audience and test users

3. Copy this installation’s callback URL

Open ZBRANO through the Home Assistant address you intend to use for connection, then open this guide from its plugin card. Copy the entire address below.

Home Assistant Ingress adds a path to this address. Keep the full path. Changing the Home Assistant address or reinstalling the add-on can change the callback; copy it again when reconnecting.

4. Create the OAuth client

  1. Open Google Auth Platform → Clients in the same project. Create a client with application type Web application.
  2. Under Authorized redirect URIs, add the exact callback copied above. This goes in redirect URIs, not JavaScript origins. Create/save the client.
  3. Copy its Client ID and Client secret. In Home Assistant → Settings → Add-ons → ZBRANO → Configuration, enter them in google_oauth_client_id and google_oauth_client_secret. Save and restart the add-on. Keep the secret in configuration, not chat.

5. Connect the intended Gmail account

  1. Reopen ZBRANO at the same Home Assistant address. Open Plugins → Catalog → Gmail Direct → Connect with Google.
  2. Select the Gmail account you added as a test user. The account owning the Cloud project can be different: the Client ID identifies the project; the account you authorize identifies the mailbox.
  3. Review the app name and permissions and approve the connection. A testing app can show an unverified-app notice; continue only if it is your own expected app. Organization restrictions may require administrator approval.
  4. Return to Plugins → Installed. Check the reported OAuth account and enabled tools. Try “List my Gmail labels” to confirm access, then “Show my five latest emails.”

Gmail troubleshooting

Error 400: redirect_uri_mismatch

Click error details in Google’s window and compare its redirect_uri with your client’s Authorized redirect URIs. Match scheme, hostname, port, full path, and trailing slash exactly. Edit the client whose Client ID is saved in ZBRANO. Save and retry after Google applies the change. The email shown on this error page is not proof that the wrong Cloud project was selected.

Google will not accept the callback address

Google requires HTTPS for web callbacks, with limited localhost exceptions, and rejects ordinary private IP hostnames. Open Home Assistant through its configured HTTPS domain, then copy that callback. A local address such as http://192.168.x.x is not interchangeable with your HTTPS address.

Wrong account, access_denied, or organization-only access

Finish resolving any invalid-request error first. ZBRANO requests an account chooser. If necessary, retry from a private browser window signed into the intended account. Add that account under Audience → Test users for an External testing app. An Internal app only accepts accounts from its organization. A Workspace administrator may also restrict Gmail access.

invalid_client or setup still required

Confirm the Client ID and secret belong to the same Web application client. Recopy them without extra spaces, save the add-on configuration and restart ZBRANO.

Insufficient permissions or Gmail API disabled

Enable Gmail API in the client’s project. Check both requested Gmail scopes, then use Reauthorize in Installed plugins to grant the missing permissions. Confirm the connected account has Gmail available.

Connection expires after about seven days

Google normally gives External testing apps using Gmail scopes a refresh token that expires after seven days. Reauthorize to continue testing. For broader distribution, follow Google’s production and verification requirements instead of treating Testing as permanent authorization.

Popup blocked or Home Assistant callback fails

Allow popups and connect in a normal browser. If the callback reports Unauthorized, reopen ZBRANO through your signed-in Home Assistant session and retry. If you changed the address, recopy and register its callback first.

Disconnect or change mailbox

Use Sign out on the installed Gmail plugin, then reconnect and choose the new account. Add it as a test user if required. You can also revoke access from Google account connections.
